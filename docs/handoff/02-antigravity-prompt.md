## 이 프로젝트의 작업 사슬 (중요 — 계획의 형태를 좌우한다)

| 단계 | 담당 | 하는 일 |
|---|---|---|
| 설계 | **당신(AGY)** | 계획서 + 테스트 명세 |
| 구현 | **Aider** | 코드·테스트 작성, 작업 단위로 git 커밋 |
| 게이트 | **Claude** | lint/build/test 실측 + diff 검토 + 다음 작업 투입 |

**구현자(Aider)는 GB10에서 도는 로컬 모델 `qwen3-coder-30b-a3b`이고 컨텍스트가 32,768 토큰뿐이다.**
따라서 계획의 각 작업은 다음을 만족해야 한다.

- 한 작업이 건드리는 파일의 **합계가 대략 15,000 토큰(≈ 52,000자)을 넘지 않을 것**
- 작업 지시가 "무엇을 어디에" 수준까지 구체적일 것 (미적 판단·모호한 지시 금지)
- 참고로 현재 CSS 규모: `src/index.css` 29.3k토큰 / `dashboard.css` 4.8k / `tour-theme.css` 3.2k / `PremiumLanding.css` 1.6k
  → **`index.css`는 단독으로도 컨텍스트를 넘긴다.** 이 파일을 건드리는 작업은 반드시 분할을 전제로 설계하라.

Aider에 맡기기 부적합한 작업(미적 판단이 필요한 디자인, 전역 CSS 재구성 등)은
`담당: Claude`로 명시해 분리하라.

## 스택 제약 (반드시 지킬 것)

- React 19.2 + Vite 8, react-router-dom 7, **순수 CSS** (Tailwind·CSS-in-JS·모션 라이브러리 없음)
- 백엔드는 FastAPI(`backend/`)가 실제 배포본. Express(`server/`)는 미배포
- 배포: 프론트 Netlify / 백엔드 Railway, 둘 다 GitHub `main` 푸시로 자동 배포
- 외부 연동은 `VITE_KAKAO_CHANNEL_URL`, `VITE_API_URL` 둘뿐. 새 유료 SaaS 도입 금지
- 새 의존성은 이유를 명시하고, 없이 가능한 대안을 먼저 검토할 것
- **테스트 러너·CI가 현재 전무하다**(테스트 파일 0개, `.github/workflows` 없음).
  검증 게이트를 세우려면 Phase 0에서 러너부터 도입해야 한다. 어떤 러너를 쓸지도 당신이 정하라.

## 산출물 2 — `docs/handoff/04-test-spec.md`

각 작업이 "됐다"를 무엇으로 판정하는지 정의한다. **테스트 코드를 쓰지 말고 명세만 써라**
(코드는 Aider가 이 명세를 보고 작성한다).

각 항목 형식:
```
[T-P0-1] 제목
  대상: 어떤 작업(P0-1)의 완료를 판정하는가
  종류: 단위 | 통합 | 수동
  전제: 필요한 상태·픽스처
  절차: 1) ... 2) ...
  기대: 무엇이 참이어야 하는가 (구체적인 값·상태·응답으로)
```

반드시 포함할 것:
- **API 계약 테스트** — `src/services/railwayApi.js`가 호출하는 모든 엔드포인트가
  배포되는 백엔드에 실제로 존재하는지 검증하는 항목. (01번 문서 B절의 불일치가 재발하지 않도록)
- **인증 가드 테스트** — 권한 없는 접근이 실제로 막히는지
- **수동 확인 항목** — 자동화하기 어려운 것은 "수동"으로 분류하되 절차를 명확히
